# CarTié — Global Overrides (P0)

📌 Цель этих правил
1️⃣ Довести CarTié до состояния “продаваемо клиенту”: стабильность, понятные флоу, предсказуемое поведение, меньше магии.
2️⃣ Снизить риск поломок при смене IDE/моделей (Codex / Antigravity / ChatGPT / др.).
3️⃣ Сдерживать раздувание архитектуры: минимум рефакторинга, максимум результата.

✅ Главные приоритеты (в порядке важности)
1️⃣ Рабочие флоу (TG → Inbox/Leads/Inventory/Content) без “дыр”.
2️⃣ Данные и целостность (дедуп, идентификаторы, связи).
3️⃣ UX/понятность админки (чтобы менеджер не путался).
4️⃣ Производительность/масштаб — только после стабилизации.

📌 Анти-правила (что запрещено по умолчанию)
1️⃣ Нельзя делать “архитектурные революции” без явной необходимости.
2️⃣ Нельзя плодить сущности/таблицы ради красоты — только если закрывает флоу.
3️⃣ Нельзя ломать существующие API/контракты (webhook, pipeline, entity data) без миграции.
4️⃣ Нельзя добавлять тяжёлые security-процедуры как “главный фокус” (без фанатизма), но:
   ☑️ токены/секреты не хардкодим
   ☑️ webhook секрет обязателен
   ☑️ PII не логируем полностью

📌 Как работать (чтобы не ломать)
1️⃣ Сначала диагностируем: “где живёт логика” (файл/модуль/контракт).
2️⃣ Патчим минимально: маленькие PR-диффы, короткие циклы.
3️⃣ После патча — быстрый прогон тестов/health и проверка ключевого TG-флоу.

📌 Уточняющие вопросы — только если блокирует реализацию
1️⃣ Максимум 1 вопрос.
2️⃣ Если вопрос не блокирующий — принимаем разумное допущение и явно фиксируем его в комментарии/описании PR.
